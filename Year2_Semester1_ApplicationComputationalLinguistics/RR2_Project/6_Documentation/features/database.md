# Feature Documentation — PostgreSQL + `pgvector` Database Subsystem (`src/db/` & `src/database/`)

## 1. Feature Purpose
The database subsystem provides relational and vector similarity storage for extracted ontology entities and their LLM-generated semantic descriptions using **PostgreSQL 16** and the **`pgvector` (`vector`) extension**. It also enforces **database isolation** so that newly executed ≤4B adaptation experiments never overwrite or mutate the protected historical replication database (`agent_om_local`).

---

## 2. Input Data
- **Extracted Entity Records:**
  - `entity` (`str`): Normalized entity identifier/label (e.g., `"author"`, `"conference"`, `"write_paper"`).
  - `description` (`str`): LLM-enriched natural-language semantic description of the entity's ontological context (parents, children, domain, range, disjoints).
  - `embedding` (`List[float]`): Dense floating-point vector generated by the active embedding provider (`768`-dim, `1024`-dim, or `4096`-dim).
- **Database Target Configuration:**
  - `DB_HOST` (`127.0.0.1`), `DB_PORT` (`5432`), `DB_NAME` (profile-specific database name), `DB_USER`, `DB_PASSWORD`.

---

## 3. Processing Steps
1. **Connection & Loopback Validation (`1_Source/db/postgres_Store.py`):**
   - Validates that `DB_HOST` resolves strictly to `127.0.0.1` or `localhost`.
   - Connects via `psycopg2` and executes `CREATE EXTENSION IF NOT EXISTS vector;`.
2. **Schema Provisioning (`init_database.sql` / `ensure_tables_exist()`):**
   - Creates the four ontology entity tables required by Agent-OM:
     - `onto_source_class (id SERIAL PRIMARY KEY, entity TEXT, description TEXT, embedding vector(D))`
     - `onto_target_class (id SERIAL PRIMARY KEY, entity TEXT, description TEXT, embedding vector(D))`
     - `onto_source_property (id SERIAL PRIMARY KEY, entity TEXT, description TEXT, embedding vector(D))`
     - `onto_target_property (id SERIAL PRIMARY KEY, entity TEXT, description TEXT, embedding vector(D))`
3. **Protected Database Guard:**
   - The historical replication database `agent_om_local` (`162` source class rows, `162` target class rows, `206` source property rows, `258` target property rows) is marked **read-only / protected** for all new adaptation runs.
   - New experiments route automatically to isolated databases based on the active profile:
     - `agent_om_adapted` (`768`-dim `nomic-embed-text:latest` for `local_4b_default`)
     - `agent_om_4b_baseline` (`768`-dim for `local_4b_baseline`)
     - `agent_om_4b_mxbai` (`1024`-dim `mxbai-embed-large:latest` for `local_4b_mxbai`)
     - `agent_om_4b_smoke` / `agent_om_test` (isolated test and smoke-run databases)
4. **Vector Similarity Search (`<=>` Cosine Distance):**
   - Executes top-$k$ cosine similarity queries (`1 - (embedding <=> %s::vector) AS similarity`) across the class and property tables during semantic retrieval.

---

## 4. Output Data
- **Relational + Vector Rows:** Populated `onto_source_class`, `onto_target_class`, `onto_source_property`, and `onto_target_property` tables.
- **Similarity Search Results (`List[Tuple[str, str, float]]`):** Top-$k$ candidate entity identifiers, descriptions, and cosine similarity scores in $[0.0, 1.0]$.

---

## 5. Main Implementation Files
- [`1_Source/db/postgres_Store.py`](../../1_Source/db/postgres_Store.py) — PostgreSQL connection manager, schema initializer, row count verifier, and `pgvector` cosine similarity query executor.
- [`1_Source/db/init_database.sql`](../../1_Source/db/init_database.sql) — Canonical DDL script for creating the `vector` extension and the four ontology tables.
- [`1_Source/database/__init__.py`](../../1_Source/database/__init__.py) — Clean package facade re-exporting database helpers under `1_Source/database/`.

---

## 6. Configuration Options
Configured in [`1_Source/config.py`](../../1_Source/config.py):
- `DB_HOST`: `"127.0.0.1"`
- `DB_PORT`: `5432`
- `DB_NAME`: Profile-isolated database name (`"agent_om_adapted"`, `"agent_om_4b_mxbai"`, `"agent_om_local"`, etc.)
- `EMBEDDING_DIM`: Vector column dimension (`768`, `1024`, or `4096`)

---

## 7. Dependencies
- PostgreSQL `16.x` server running on `127.0.0.1:5432`.
- `pgvector` (`0.8.0`) PostgreSQL extension (`CREATE EXTENSION vector;`).
- `psycopg2-binary` (`2.9.10`) Python driver.

## 9. Known Limitations
- Because `pgvector` columns are typed to a fixed dimension (`vector(768)`, `vector(1024)`, or `vector(4096)`), switching to an embedding model with a different dimensionality requires either using its dedicated isolated database (e.g., `agent_om_4b_mxbai` for `1024`-dim) or recreating the tables in the target scratch database.
